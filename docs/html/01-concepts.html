Chapter 01

Concepts

The vocabulary the whole codebase is written in. Everything here is behaviour and data model — no implementation yet. If you read only one chapter before touching the code, read this one.

The problem

On macOS the set of open windows is flat. Cmd+Tab walks applications, Cmd+backtick walks the windows of one application, and both walk all of them. If you have a code editor, two terminals, and a simulator open for one project, and a browser, a chat client, and a document open for something else, the switcher mixes them. The cost is not the extra keystrokes; it is that switching context between tasks requires reconstructing a window arrangement by hand every time.

The system's own answers are Spaces and the built-in Space Manager. Spaces partition windows but bind that partition to a full-screen desktop with an animated transition and their own switching gestures. The built-in Space Manager groups windows but keeps a single global switcher. Neither makes the guarantee Debut is built around:

The central guarantee

No keyboard-driven window switch ever crosses a space boundary. The switcher, the same-app cycler, and the number shortcuts are all scoped to the active space. Leaving a space is always a deliberate act.

Space

A space is a workspace: a set of windows scoped to one task. Exactly one space is active at any moment.

Two properties make spaces cheap. First, a space is not a desktop — windows in inactive spaces are not moved, resized, minimised, or sent to another Space. They stay exactly where they are and are simply occluded by a full-screen window Debut owns. Switching spaces therefore has no animation to wait for and cannot disturb your layout. Second, a space has no name. Its label is its 1-based position in the list, computed on demand. A change in the space list therefore requires no bookkeeping at all: afterwards the labels are already correct, because they were never stored.

Why no names

Rename was implemented and then removed. A stored name is state that must be migrated, displayed, edited, validated, and kept consistent with position-based shortcuts. A derived label is none of those things. The position numbers still drive the jump and quick-switch shortcuts, but they are deliberately not drawn on the stages — the stack's vertical order is the affordance.

Window

Debut tracks individual windows, not applications. A space holds window entries, so one application can own windows in several spaces at once — one editor window per project, one terminal per project. This is the single most consequential modelling decision in the product, and it is what forces most of the complexity in chapters 3 and 7.

A window has two identities, and keeping them apart matters:

Runtime identity — the CGWindowID
A number the window server assigns. It is unique while the window lives and meaningless afterwards. It changes when the owning application restarts, and it is never written to disk as a durable key.
Persistent identity — (bundle ID, window title)
The pair used to recognise a window across sessions. It is the best available key and it is still not reliable: terminal prompts, browser tabs, and chat channels all change the title while the window is the same window.

Because the persistent key is unreliable, matching a saved assignment to a live window is a ranked operation with fallbacks rather than a lookup. Chapter 7 covers the algorithm.

What counts as a window

Only real, non-modal windows are tracked. In Accessibility terms that means the element's role is a window and its subrole is either a standard window or a dialog, and it is not modal. Modal sheets, floating palettes, toolbars, shadows, and unclassifiable popups are excluded. A window whose owning application is not a regular foreground application, or which has no bundle identifier, never enters the model.

Stage

A stage is a space's representation inside the overlay: a horizontal row of window previews, each badged with its application icon and captioned with its title. Stages stack vertically, the active one centred at full scale, the others scaled down by a configurable factor that compounds with distance.

A stage carries no title of its own, because a space has no name. There is no full-screen backdrop and no background blur behind the stack — the stages float directly over whatever is on the desktop. The selection is expressed by magnifying the selected preview rather than by drawing a selection chrome around it.

Session

The activation shortcut is not a toggle. It starts a session bounded by a held modifier, and the session and the overlay are two separate pieces of state:

  • Tap — press and release before the presentation delay elapses. The overlay never appears; Debut switches to the most recently used window in the active space. This is the "flip to the previous window" gesture, and it must feel instant.
  • Hold — keep the modifier down past the delay. The overlay appears and further keypresses navigate it.
  • Escape — closes the overlay but leaves the session alive. A further navigation keypress reopens it. This is why "overlay visible" and "session active" cannot be the same boolean.
  • Release the modifier — commits the current selection and ends the session.

Quick switch is the exception that proves the model: the number chords switch space immediately, with no session and no overlay, and they dismiss the overlay first if it happens to be open.

Inside a full-screen Space

The overlay is presented over a full-screen app too, and every shortcut behaves as it does on the desktop. The overlay window joins all Spaces at .statusBar level, so the stages reach the Space the user is actually looking at.

What does not follow is the desktop surface, which must stay off other Spaces or it would cover the full-screen app. Inactive spaces are therefore not occluded in there — the full-screen app already covers them. The probe in setupOverlay() SpaceController.swift:624 still asks the question, but only to publish focusedWindowFullscreen in the diagnostic state block; it no longer rejects the presentation.

MRU ordering

Within a space, windows are ordered by recency — index 0 is the most recently focused. This ordering is not a decoration; it is the model's only ordering, and several behaviours read directly off it:

  • A tap of the activation shortcut targets index 1, the second most recent window, which is what makes tap-to-flip work — unless the frontmost app is excluded, in which case it targets index 0, because from an excluded app the "previous window" is the space's most recent one SpaceController.swift:568.
  • Opening the overlay preselects index 1 for the same reason, so a single activation lands on the previous window — subject to the same exclusion rule, and to the space holding at least two windows :580.
  • Changing space inside the overlay resets the selection to that space's index 0 — its own most recent window.
  • Quick switch focuses the destination space's index 0, or, in the same-app variant, that space's most recent window belonging to the application you were already using.

Recency is maintained strictly from events — focus changes within an application and activation notifications across applications. Nothing polls.

Assignment rules

Every tracked window belongs to exactly one space. There is no sharing and no duplication. Three rules cover how a window gets there:

Situation Result
A brand-new window appears (Cmd+N, code .) It joins the active space, even if the same application already has windows in other spaces. New work belongs where you are.
An existing window is activated from outside Debut (Dock, Spotlight) Debut switches to the space that already owns it. The window does not move. Activation is a navigation act, not a re-assignment.
The window belongs to an excluded application It is invisible to the whole system, filtered at every layer.

Exclusions

There are two independent exclusion lists, and conflating them is a common mistake:

Excluded apps
The application is not tracked at all. Its windows never appear on a stage and never take part in switching. The filter must be applied in discovery, in launch handling, in activation handling, in reconciliation, and in the Accessibility observer — missing any one layer lets the application back in through that path.
Quick-switch exclusions
The application is tracked normally, but while it is frontmost it keeps its own number shortcuts. This exists so that an app which binds Ctrl+1..9 itself is not shadowed by Debut's space jumps.

Dormancy

This is the concept most often missed on a first read, and it is the reason Debut survives a reboot usefully.

When an application exits, its windows leave the live space view — but their space and their position within it are retained as dormant assignments. When that application launches again, Debut reclaims those positions: first by exact bundle-and-title match, then, for applications whose titles are dynamic, by a complete one-to-one match of the remaining windows of that bundle.

Two properties are deliberate and both are load-bearing:

  • There is no time-based expiry. A dormant assignment is not a cache entry. It survives an app being quit deliberately, being restarted by an updater, and the machine being rebooted, because macOS does not reliably let Debut distinguish those cases anyway.
  • Absence is never proof of destruction. A window missing from an Accessibility or window-server snapshot may merely be hidden or ordered out. Only a real lifecycle event — a destroy notification, an explicit exclusion or reset, or the deletion of the containing space — removes an assignment.
Why this rule is absolute

The tempting shortcut is to treat "not in the current snapshot" as "closed" and clean up. Doing so deletes a user's layout on any transient failure, and transient failures are routine: an app still warming up can momentarily report a standard window as a dialog. A misreport that produces dormancy is self-healing on the next snapshot. A misreport that produces deletion is permanent layout loss.

What is persisted

State survives restarts and reboots. Persisted: the list of spaces and their order, the window-to-space assignments (keyed by bundle ID and title), the dormant assignments, the active space, and all settings. Not persisted: anything ephemeral — window IDs, process IDs, and the runtime tracking tables, all of which are rebuilt from scratch on launch.

On launch Debut loads the snapshot, reconciles it against the live window list, adds any live windows the snapshot did not know about, prunes empty spaces that hold no dormant assignments, and then activates the space owning the currently focused window rather than always starting at space 1.
