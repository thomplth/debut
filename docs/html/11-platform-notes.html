Chapter 11 · Appendix

Platform notes and glossary

Most of Debut's non-obvious code exists because macOS behaves in a way that is not documented, or is documented and wrong. This appendix collects those constraints in one place, each with the evidence that established it, so a future change can be checked against them without re-deriving each one the expensive way.

Window identity

CGWindowIDs are ephemeral. They change between app restarts, and a window that is closed and reopened gets a new one. Never persist them. The stable cross-session key is (bundleID, windowTitle), with bundle-only matching as a fallback because titles are not stable either (chapter 7).

Absence from a snapshot is not evidence of destruction. Hidden, minimised, and ordered-out windows disappear from both AX and CGWindowListCopyWindowInfo. Only kAXUIElementDestroyedNotification, explicit exclusion or reset, or stage deletion may remove a live assignment. This rule has its own test — "CG absence never removes a window without a lifecycle event".

AX role and subrole are a snapshot, not a verdict. An app still warming up can report a standard window as a dialog or a panel. An untrackable classification must make an assignment dormant, never delete it. Deleting turned a momentary misreport into permanent layout loss: it stranded a browser's four windows, which returned as reason: new and collapsed into the active stage. Dormancy makes the same misreport self-healing on the next snapshot.

Window manipulation

The desktop surface, restated. Since windows can be neither moved off screen nor made transparent, Debut occludes them: a Debut-owned full-screen NSWindow at .normal level, ordered between the active stage's windows and everything else. Order the surface to front, then AX-raise the active windows above it. No position or minimise manipulation is involved at all.

It must not set .canJoinAllSpaces — that makes it follow into fullscreen Spaces and cover the fullscreen app. The surface only matters on the normal desktop.

Screen capture

CGWindowListCreateImage corrupts silently and per app. macOS 15 obsoleted the family and the package no longer targets a version that can call it, so this is now a rule about capture paths in general rather than about one API. It did not fail cleanly and it did not fail uniformly: measured on macOS 26.5.2 across 21 live windows, 18 captured real content while one app's windows came back as a uniform grey image. Because most windows still looked right, the failure hid.

Never treat a non-nil capture as proof of content. Assert that a capture contains more than one distinct luminance value — this is exactly what the E2E scenario "Window previews contain non-uniform captured pixels" and the containsVisibleContent guard do. Use ScreenCaptureKit wherever the result must actually contain pixels.

Capture cost is per window, not per pixel. SCScreenshotManager costs 12–17 ms per window regardless of the requested size; 400 px thumbnails measured the same as full resolution. Requesting smaller images is a memory optimisation, not a latency one.

Capture concurrently — 21 windows took 398 ms serially versus 163 ms concurrently — but expect sublinear scaling: the same run burned 1.8 s of CPU for 163 ms of wall time. The only large win is capturing fewer windows. Hence the preview cache policy in chapter 6.

Wallpaper

  • The wallpaper cannot be resolved from its configuration. Providers such as com.apple.NeptuneOneExtension and com.apple.wallpaper.extension.photos generate images and expose no file. The wallpaper store and desktopImageURL are both dead ends. Capture the pixels macOS already rendered instead.
  • SCShareableContent.excludingDesktopWindows describes the returned list, not your intent. Pass true so desktop windows stay out of the list, then hand that list to SCContentFilter(display:excludingWindows:) to composite wallpaper without UI. Passing false puts the wallpaper into the list, and excluding it leaves the filter with nothing to composite — which fails at capture time with error -3811, not at filter construction.

Binding lookup is exact KeyCombo equality across all four modifier booleans (EventTapKeyboardService.swift:408, Models/KeyBinding.swift:398), so a combo with Option set can never match the bare-Tab binding.

No app queries inside the event-tap callback. Workspace and cross-process Accessibility calls block keyboard delivery for the whole system and can get the tap disabled outright. Cache the frontmost bundle ID from NSWorkspace.didActivateApplicationNotification; quick-switch app priority is then an in-memory set lookup. This applies to diagnostics too — report the fact, let the main queue enrich it.

Process and lifecycle

  • All three discovery paths must register tracking. Startup reconciliation, app launch, and focus-change (Cmd+N) all need registerTracking so the window gets kAXUIElementDestroyedNotification and kAXTitleChangedNotification. Missing any path produces ghost windows.
  • Process exit makes assignments dormant, not deleted. Track every window-owning PID with an event-driven DispatchSource.makeProcessSource(.exit); keep didTerminateApplicationNotification only as a backup. Both signals funnel into one idempotent cleanup path. PID monitoring must survive AX observer pruning and must not depend on window visibility.
  • There is no time-based expiry on dormancy. A relaunch restores exact bundle+title matches first, then complete one-to-one bundle matches for dynamic titles.
  • macOS does not reliably distinguish termination reasons, so dormant assignments must survive deliberate quits and updater relaunches alike.
  • Every destructive assignment change must report a diagnostic event. A removal that emits nothing is unfalsifiable afterwards. The untrackable-deletion bug above left no trace; the log showed only a harmless-looking windows_reconciled summary and the damage had to be inferred from a later reason: new.

Performance and SwiftUI

Never leave an NSHostingView attached while the overlay is hidden. SwiftUI keeps running layout passes on ordered-out windows and consumes 50 %+ CPU indefinitely. Remove the hosting view in hideOverlay() and recreate it in showOverlay().

  • No polling, no timers. Everything is event-driven: AXObserver for focus, NSWorkspace notifications for app lifecycle, DispatchSource for process exit, filesystem watches for the wallpaper directory. Even the stall watchdog schedules nothing unless a presentation is in flight.
  • Observe the frontmost app only. Move the AXObserver for kAXFocusedWindowChangedNotification when didActivateApplicationNotification fires, rather than observing every app.
  • Scale is a render transform, not a layout change. Changing layout geometry per frame re-runs layout for the whole stack; a scaleEffect does not (chapter 6, KHA-448).

Glossary

Assignment
The record that a particular window belongs to a particular stage at a particular index. Either live (the window exists now) or dormant.
AX / Accessibility API
Apple's cross-process UI automation interface. Debut's only supported route to another app's windows. Requires a user-granted TCC permission.
Committed vs tentative selection
Tentative is what the overlay highlights while you cycle; committed is what actually happened when the session ends. Escape discards a tentative selection.
Desktop surface
The full-screen Debut-owned window used to occlude inactive stages. Not a wallpaper — it renders the captured wallpaper image so that occlusion looks like an empty desktop.
Dormant assignment
A stage placement retained for a window that no longer exists — because its app quit, exited, or briefly misreported its AX role. Persistent, with no expiry.
Lifecycle vs transient (diagnostics)
Lifecycle events are appended to the durable JSONL log; transient events live only in the snapshot. Both refresh the state block.
MRU
Most-recently-used ordering. In Debut it is simply the order of the array — no timestamps. Index 0 is the current window, so index 1 is the default selection: one Tab press means "the previous window".
Plate
The visual representation of a stage in the overlay. Stages are the model; plates are the render.
Provisional window ID
An ID recorded during reconciliation as possibly-replaced, carried forward so a later pass can recognise a replacement without a timeout.
Reason code
The string on a reconciliation diagnostic event explaining why a window landed where it did — new, dormant restoration, bundle-only recovery, and so on. A cluster of new after a restart means recovery failed.
Session
The interval during which the activation modifier is held. Separate from overlay visibility.
Stage
A workspace. Has no name — its label is its 1-based position in the array, so a change in the stage list needs no bookkeeping.
Trackable
An AX classification: a standard window Debut may manage. The classification is tri-state — trackable, untrackable, or neither (unknown), and the third case must not be collapsed into the second.
Trace ID / correlation ID
Correlation ID identifies one performance span; trace ID stitches spans into a single overlay presentation. A span joins a trace via updateTraceID.

Known rough edges

Documented here so they are not mistaken for intent. Check the spec before "fixing" any of them:

  • deleteStage index arithmetic. min(overflowIndex, stages.count - 1) mixes a pre-removal index with a post-removal count, and has no test coverage (chapter 4).
  • Deployment-target mismatch. Package.swift says macOS 26, Info.plist says 14.0 (chapter 10).
  • Duplicated plateCenterY maths in the overlay, deliberately retained as a cross-check rather than factored out (chapter 6).
