Ground-up documentation

Debut

Debut is a stage-based workspace manager for macOS. It replaces the system app switcher with isolated workspaces, so that cycling windows never crosses a workspace boundary. This series explains the product from first principles and then all the way down into how it is implemented.

What Debut does

macOS gives you one flat list of windows and one switcher that walks all of them. Debut partitions that list into stages. Exactly one stage is active. The window switcher, the same-app cycler, and the number shortcuts all operate inside the active stage only. Windows in other stages are not moved, minimised, or resized — they are simply covered by a full-screen window Debut owns, so switching stages costs no animation and no window geometry changes.

Holding the activation shortcut opens an overlay that shows every stage as a horizontal plate of window previews, stacked vertically with the active stage centred. You navigate it with the keyboard or the pointer, and you can drag windows between stages or drag stages into a different order.

The project at a glance

LanguageSwift 6.2, swift-tools-version: 6.2, strict concurrency
Build systemSwiftPM only. There is no Xcode project; the .app is assembled by a shell script.
DeploymentPackage targets macOS 26; the shipped Info.plist declares LSMinimumSystemVersion 14.0
UIAppKit windows hosting SwiftUI views. No SwiftUI App lifecycle, no @main.
Size~22k lines across sources and tests; the largest single file is the overlay view at ~1.6k lines
Tests100% swift-testing (no XCTest), plus a shell-based CI contract suite and an E2E harness
SandboxDisabled. Controlling other applications through Accessibility is impossible inside the sandbox.
NetworkNone in a stock build. Telemetry has no credentials configured in the shipped Info.plist.
